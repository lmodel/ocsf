# Datasets

* [ocsf LinkML schema](ocsf-linkml-schema.md) - The LinkML model of the Open Cybersecurity Schema Framework 1.9.0, `src/ocsf/schema/ocsf.yaml` (schema id `https://w3id.org/lmodel/ocsf`): an umbrella over `ocsf_core`, `ocsf_objects` and a module of event classes per category, written by a script from OCSF's own files with OCSF's keys and integer values.
* [Core module](core-module.md) - `src/ocsf/schema/ocsf_core.yaml`, the module with OCSF's data types, the dictionary attributes whose value is not an object, the three lists OCSF writes as strings, and `OcsfFacts`, which declares the schema's annotation keys.
* [Objects module](objects-module.md) - `src/ocsf/schema/ocsf_objects.yaml`, the module with OCSF's objects, its profiles as mixins, the extensions' objects and the dictionary attributes whose value is an object, which sit together because they refer to each other.
* [Event class modules](event-modules.md) - The modules `src/ocsf/schema/ocsf_events_*.yaml`, which hold the base event, a module of event classes per OCSF category and the Windows extension's event classes: 87 classes a concept may name, and OCSF's abstract parents such as `OcsfIamEvent`.
* [Generated artefacts](generated-artefacts.md) - What `just gen-project` and `just gen-doc` generate from the ocsf schema: the projections in `project/`, the Python models in `src/ocsf/datamodel/`, and the merged schema in `docs/schema/`. None is edited by hand.
* [Example data](example-data.md) - The examples `tests/test_data.py` checks: the least each class and object requires, hand-written events, a counter-example of each kind of constraint, and one of each rule the JSON Schema cannot state. The test also makes a counter-example of every list, constant and required attribute.
* [Samples from OCSF's server](server-samples.md) - `tests/data/ocsf-server-samples-1.9.0.json.gz`, what OCSF's server generated for each event class on 2026-11-04, with what OCSF's validator found in each. They show that every key and listed number the generator writes exists here, and that the rules find what OCSF's validator finds.
* [Verdicts on real events](real-event-verdicts.md) - `tests/upstream/ocsf-examples-verdicts.json`, what OCSF's validator found in each of the 93 events of ocsf/examples at a pinned commit, with no text of the events. `scripts/check_real_events.py` compares this schema's verdict with it.
* [Copy of the upstream](upstream-copy.md) - `upstream/`: OCSF's files at the tag 1.9.0, unchanged, and what OCSF's compiler makes of them. `scripts/check_upstream_release.py` pins each copied file by its git object hash, and a test on Python 3.14 compiles the folder again and compares the bytes.
* [The schema's adapt copy](adapt-copy.md) - `.lokf/ocsf.yaml`, the copy `just lokf-adapt` writes from the schema so that it sits beside LOKF's `lokf.yaml`: rooted on `OcsfBaseEvent`, with the 20 keys LOKF also defines renamed with an `ocsf_` prefix and their IRIs kept.
* [Neighbours' adapt copies](neighbour-copies.md) - The adapt copies of thirteen released lmodel repositories in `tests/neighbours/`, among them cve, cwe, kev-catalog, nist-nvd, attack and stix. A test holds the names apart from them and pins the keys they share, and the mappings are held to them.
* [D3FEND term list](d3fend-term-list.md) - `tests/upstream/d3fend-terms.txt`, the names of the D3FEND 1.6.0 terms that OCSF's references name, each found in D3FEND's pinned file by `scripts/extract_d3fend_terms.py`.
* [A logon over SSH](example-authentication-event.md) - An authentication event written as a concept of type `OcsfAuthentication` in the adapt copy's keys. It shows that the domain schema admits an event as a concept, with its numbers as OCSF writes them.
